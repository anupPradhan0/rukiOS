Configuration locations and mutability

Existing machine configuration remains owned by its system manager. rukiOS configuration paths below are proposals and do not currently exist in this repository.

Path/interfaceWhat belongs thererukiOS status and access rule
/etc/ruki/Proposed machine-wide rukiOS settings.PROPOSED Not present today. Admin-managed; ruki displays settings read-only at first. Mutations should use a validated tool, not silent file edits.
~/.config/ruki/Proposed per-user preferences such as keymap overrides and TUI display choices.PROPOSED Not present today. User-readable/writable text config; never store credentials or agent secrets in plain text.
/etc/systemd/system/Local system service units and administrator drop-ins/overrides.Existing system-owned configuration. Inspectable; write only through an explicitly scoped future service-configuration workflow. The current service controls do not edit it.
/usr/lib/systemd/system/Package-provided vendor service units.Existing package-managed configuration. Read-only for ruki; do not edit vendor files directly.
/etc/NetworkManager/system-connections/NetworkManager connection profiles; may contain passwords/private keys.Existing sensitive system config. Out of first-release outcomes; do not display secrets to TUI, CLI output, logs, or agents.
/proc/*, /sys/*, /etc/os-release, journal via journalctlKernel runtime state, hardware readings, OS identity, and logs.Current inspection sources; read-only to ruki. Errors/unsupported readings should be reported as unavailable, not zero.
Configuration rule: there is no current rukiOS settings directory. Keep system state readable through Linux's existing interfaces, add /etc/ruki and ~/.config/ruki only when a real setting requires them, and make every writable setting's owner, scope, validation, and permission explicit.

Current command surface

Read-only CLI commands already present

ruki system, disk, memory, network, health [--json], services, processes [N], and logs [N].

Only health has a documented JSON output. Other commands currently produce human-readable text.

Mutation routes already present

System Console service start/stop/restart with confirmation; standalone monitor process SIGTERM with confirmation.

There are no corresponding service/process mutation CLI commands, no ruki config editor, and no agent action tools.

Interface contract to build toward

Read tools

  • Stable structured output for health and process/service status, suitable for CLI scripts and agents.
  • Mark each field as available, unavailable, or permission-limited.
  • Document its source, refresh behavior, and whether it can change system state.

Write tools

  • Expose named actions, not generated shell strings (for example, service start/stop/restart by validated unit name).
  • Show the target and expected effect; require confirmation for process/service changes.
  • Return success/failure and a record of the attempted action; preserve system permissions.

System path references: systemd unit directories; NetworkManager keyfile locations and permissions. Existing commands and filesystem reads were checked in this repository on 13 Oct 2026.
