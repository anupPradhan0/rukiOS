This is the shared target map for the ruki System Console and ruki-monitor. Arrow keys remain available. Context-specific actions are shown in each screen; risky actions always require a visible confirmation.

Move and select

j / ↓Move down through rows or the vertical section list.
k / ↑Move up through rows or the vertical section list.
h / ←Move focus to the previous side-by-side panel when one exists.
l / →Move focus to the next side-by-side panel when one exists.
Tab / Shift-TabMove to the next / previous panel or section.
EnterOpen or activate the selected item when that view supports it.

Find and navigate

/Start searching or filtering the current list.
EnterApply the search; while confirming an action, accept it.
EscCancel search/modal first; otherwise leave the current TUI.
PgUp / PgDnMove by one page in a long list or view.
Home / End · g / GJump to the first / last item where list navigation applies.
1–9 / 0Jump to numbered sections where shown.

What we can learn from Omarchy

Omarchy is a desktop distribution using Hyprland, so its global Super-key shortcuts are a different layer from rukiOS TUI keys. The useful design ideas are discoverability and clear separation of shortcut scopes:

  • Make the map easy to summon: Omarchy exposes its desktop bindings with Super + K; its manual also lists separate key lists for Tmux and Herdr. rukiOS should provide a visible in-app ? help view in each TUI and keep any future global shortcuts in a separate map.
  • Separate global and local controls: Omarchy uses Super-modified chords for desktop actions (for example, Super + Space opens its menu and Super + 1–4 selects workspaces). Tmux then has its own prefix and a vi-style copy mode. For rukiOS, keep system TUI actions local and consistent; do not copy desktop Super bindings into list navigation.
  • Keep user overrides maintainable: Omarchy documents a user-owned ~/.config/hypr/bindings.lua, an in-menu setup path, and loading user bindings after defaults. This is a useful future model for rukiOS customization: documented user overrides rather than editing package-managed defaults directly.

On Omarchy, Super + K lists desktop bindings, Super + Alt + K lists Tmux keys, and Super + Ctrl + K lists Herdr keys. Your local overrides may differ. Sources: Omarchy Hotkeys manual (keybinding viewer and desktop/Tmux maps); Omarchy Dotfiles manual (user keybinding overrides); Omarchy Hyprland configuration guide (binding file and validation guidance). Omarchy's full shortcut list also includes media, capture, notifications, display settings, web apps, and other optional applications. Keep those only where rukiOS ships the corresponding feature; do not bind mouse-only window dragging or scrolling.

Compatibility and no-mouse rule: these are proposals, not bindings implemented today. Omarchy already claims several Super chords; when ruki runs inside Omarchy, never override the host's bindings. In a standalone rukiOS compositor session, provide defaults with editable user overrides. Do not copy mouse drag/resize/workspace-scroll operations: provide keyboard equivalents. The TUI, CLI, and text console must remain usable without a compositor.
